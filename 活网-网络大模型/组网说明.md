# 组网 · 不用死挂同一个信箱，活体自己找到彼此

## 为什么不再用信箱

"同一个信箱"是从 git 借的权宜：要人事先约定一个中心地址，谁都能删分支，是单点。
真实网络里节点互认不靠这个，靠三层机制——本包 `组网.py` 取其原理，纯标准库实现：

| 机制 | 原理来源 | 解决什么 |
|---|---|---|
| mDNS 零配置发现 | python-zeroconf / RFC6762 | 同网段节点喊话即互相看到，不用配地址 |
| SWIM/Gossip 名单传染 | icgood/swim-protocol、SWARM 三层架构 | 每个包捎带全部已知成员，一传十十传百，无中心名单 |
| CRDT 确定性收敛 | gossip 协议文档所列 CRDT | 状态合并无需仲裁，任何节点算出的账字节相同（sha256 可核） |

## 怎么用（三行）

```powershell
cd <包根>
python 组网.py daemon          # 常驻：自己喊话、发现同伴、合成一本账
python 组网.py status          # 看当前已知成员和联邦账
python 组网.py selfcheck       # 自检：3 独立节点零配置发现 + 账收敛
```

- **同一局域网 / 同一台机器**：两边都跑 `daemon` 即可，零配置，自动发现。
- **跨网段（如百度搭子云端 ↔ 本地）**：组播出不了网段，需给一个可达同伴地址引导：
  ```
  python 组网.py daemon --seed 对方IP:45222
  ```
  seed 只是引导——接上后名单自行传播，**seed 死了网络照常**，不是中心信箱。

## 实测（不是推断）

- 内存总线模拟：3 独立节点，各自不同成长 → 每节点都看到全部 3 个成员、账 sha256 去重为 1、三节点独有词全进同一本账。
- 真实 UDP 组播：两个独立 Agent 在同一网段 → 互相发现（各 2 成员）、账 sha256 完全相同（755de2ccde3f…）、各自独有词都并进账。
- 只增不改：新增 `组网.py` 一个文件，原有文件零改动。

## 诚实边界

- 身份是随机 node_id，可冒名；认宗靠 convention_root 全等，异宗不并。
- 组播不出网段——跨网段必须有 seed 引导口，这是分布式系统铁律，mDNS/DHT/区块链都绕不开；但 seed 可随时更换、不是单点。
- 传的是口径摘要（合并规则/词表/负载/忆层指纹），私技字样字段拒发；阈值未落账、不可汇聚。
- `组网.py` 与旧的 `gitbox.py`/`成长桥.py` 并存，前者零配置、后者走中心信箱，按需选，互不覆盖。
