# 阶段一 · 基准校验底座

规约的“根锁”。它不参与任何 AI 推理，只是**点火前必须先过的一道硬闸门**。
本阶段做完，智能体可以还没有模型、没有勘比引擎、没有区块链，但**绝不能没有这道闸**。

---

## 一、目录树

```

├── convention/
│   ├── 本源规约.md           # 唯一权威文本（只读 444）
│   └── archive/v1.md …       # 每次变更前的旧版自动归档
├── anchor/
│   ├── genesis.json          # 创世锚（只读 444）：登记规约口径、校验器指纹、变更阈值

├── amend.py                  # 规约变更闸门（提案→审签→提交）

```

## 二、点火怎么用

```bash
python3 fireup.py init        # 仅首次：生成创世锚 + 锚链首行 v1
python3 fireup.py check       # 每次点火：四道闸门
python3 fireup.py show        # 只读：打印当前有效锚
python3 fireup.py check --json   # 供上层调度进程解析
python3 fireup.py init --rekey --reason "升级说明"   # 只换校验器/基因锁登记，不动锚链历史
```

上层程序的标准接法（这是“拒绝加载”的落地方式）：

```python
import subprocess, sys
r = subprocess.run([sys.executable, "阶段一-基准校验底座/fireup.py", "check"], capture_output=True)
if r.returncode != 0:
    print(r.stdout.decode())      # 打印拒绝原因
    sys.exit(r.returncode)        # 主进程直接死掉，模型/勘比/记忆一律不加载
# 只有走到这里，才允许 import 勘比引擎、装记忆台账、拉模型
```

## 三、退出码（判据，不看文字看码）

| 码 | 含义 | 处置 |
|---|---|---|
| 0 | 四闸全过 → 点火放行 | 允许加载下层 |
| 1 | 规约内容偏离当前有效锚（改字、加空行、换编码都算） | 拒绝点火 |
| 2 | 锚链损坏（断链、跳版、行内摘要自相矛盾、被插队） | 拒绝点火 |
| 3 | 校验器本体被改动（fireup.py / amend.py 指纹不符） | 拒绝点火 |
| 4 | 创世锚或锚链缺失 / 不可解析 | 拒绝点火 |
| 5 | 规约文件缺失 | 拒绝点火 |
| 6 | 基因锁缺失、被改动，或登记被清空 | 拒绝点火 |

**没有“跳过校验”的开关，也没有 `--force` 用于 check。** 这是刻意的：一次“图方便”的开关，就是整道闸失效的开始。

## 四、摘要口径（报数前先自证，避免日后对不上）

- 算法：主 `SHA3-256`，副 `SHA-256`（双算，防止单一算法被换）
- 对象：**文件原始字节**，UTF-8，保留全部空行与文末换行
- 字节数：`len(raw)`
- 行数：`raw.count(b"\n")`，等同 `wc -l`
- 首版实测：5911 字节 / 49 行 / `SHA3-256 = 5be3989c934bfa42b9a7c847c550ef298f4359a4e0e5b7e3080ac3db47095833`
- 校验器指纹：`fireup.py`、`amend.py` 各自 SHA3-256，登记在 `genesis.json` 的 `loader` 字段

> 注意：改一个中文全角标点、增一个空行，都会让摘要变、让退出码变成 1。这是设计意图，不是 bug。

## 五、规约怎么改（变更闸门，fail-closed）

“任何人不得直接修改本规约”——在代码层面落实成四步：

```bash
# 1 提案：声明理由 + 指定拟议新文本（冻结时间点，登记 from_root 与 target 摘要）
python3 amend.py propose --by EXAMPLE-01 --reason "补入医疗链条款" --new-file ./draft.md

# 2 审签：不同节点各自独立签，approve / reject 都可
python3 amend.py attest --proposal proposals/P-xxx.json --node NODE-A --decision approve --note "已核对"
python3 amend.py attest --proposal proposals/P-xxx.json --node NODE-B --decision approve --note "已核对"

# 3 提交：满足全部判据才生效
python3 amend.py commit --proposal proposals/P-xxx.json --new-file ./draft.md

# 4 复核
python3 fireup.py check
```

自动闸门判据（写死在代码里，不接受参数绕过）：

1. approve 数 ≥ `amend_threshold`（创世锚登记，阶段一 = 2）
2. 审签节点必须唯一（同一 node 重复签只算一份）
3. 存在任何 reject → 提案直接否决，规约保持原样
4. 每份审签绑定的 `proposal_sha3` 必须与当前提案一致（提案被改，旧审签全部失效）
5. 拟议文本实测摘要必须与提案登记的 target 一致（提案后偷偷改文本 → 作废）
6. 提案登记的 `from_root` 必须等于当前链尾 root（防止基于过期锚提案）

达标后的动作：旧版复制到 `archive/vN.md` → 新文本落盘并 chmod 444 → 锚链追加 `v(N+1)`，`prev_root` = 旧 root。

## 六、基因锁（闸 3.5）

规约第三章 6～9 款是**不可删减**的四条：不可转让、不可被代表、不可改根、**不可信任缔造者**。最后一条是刻意加的——连缔造者本人也不被信任为中立，不得以「我是它的创造者」取得任何例外。它们不靠自觉守住，靠两道机械拦截：

- **amend.py 提交前拦**：拟议新文本若缺这四款中的任何一款、或重复出现，直接判提交作废，进不了锚。
- **fireup.py 闸 3.5 拦**：拿规约里那四款**整行逐字**算 SHA3-256，与登记值比对。改一个标点、换一个全角半角，都判"被改动"，退出码 6。

还有一条反绕过的判断：**规约里明明有这些条款、登记却是空的**，只可能是有人把登记清掉了 → 直接拒绝点火，不许"清空登记即跳过"。这一条是实测用例 C 逼出来的，原本是个真漏洞。

> 基因锁的登记在创世锚里（`gene_lock.clauses`）。换校验器代码或重登记，用 `init --rekey`，会把旧指纹压进 `loader_history` 留痕，锚链历史不动。

## 七、能力边界（必须明说，不许夸大）

**这套东西在阶段一能防什么：**

- 防误改：任何人不小心动了规约一个字，点火立刻失败，不会带着被改的规约跑起来
- 防偷改校验器：改了 fireup.py / amend.py，闸 1 直接拦（退出码 3）
- 防偷偷换版本：换来的文本哈希对不上链尾，退出码 1
- 防无共识改规约：单人或单节点签不动，必须过阈值且无 reject
- 防伪造锚链：删行、跳版、prev 断开，退出码 2
- 防偷删基因锁：走流程被 amend 拒；绕流程改内容＋重签自洽锚，被闸 3.5 抓（退出码 6）
- 防"清空登记"绕过：规约有三款而登记为空，一律拒绝点火

**阶段一防不住什么：**

- 防不住有物理权限的人：他可以同时改规约 + 重算哈希 + 重写锚链 + 重写创世锚，本地全链路自洽地伪造一遍。**本地比对的极限就在这里。**
- 防不住“合法变更但方向错误”：如果 2 个审签节点同时被收买，闸门照样放行。这是阈值问题，靠阶段三扩节点、阶段四上链解决。

**所以阶段一的正确定位是：**

> 把根锁在这里立稳，让一切改动必须留痕、必须过闸、必须能复盘；
> 真正的“不可篡改”由阶段四把锚哈希写进链上、由多方独立节点共同维护来完成。

这也正是本源规约第三条（治理权限铁律）在代码层的第一次兑现：**人只能提案，不能直接改；闸门只认哈希和共识，不认身份。**

## 八、与后续阶段的接口

| 阶段 | 接什么 | 接在哪 |
|---|---|---|
| 阶段二（单点原型） | 勘比闭环 / 关系引擎 / 记忆台账 | 全部加载代码放在 `fireup.py check` 返回 0 之后 |
| 阶段三（分布式节点） | 节点准入、跨节点交叉审签 | `amend_threshold` 随节点规模上调；审签件改由各节点本地生成后同步 |
| 阶段四（链上确权） | 锚哈希上链、链上仲裁熔断 | 把 `anchor_chain.jsonl` 每行 `root_sha3` 上链锚定，本地链只做镜像 |

## 附：本包内的三条「自己试一次」

脱名可公开版里，规约文件设为**可写**（644），是为了让你能亲手验证下面三件事；验证完请 `chmod 444` 还原。

1. **原样**：`python3 fireup.py check` → 退出码 **0**（点火放行）。
2. **改一个标点**：把 `convention/本源规约.md` 里任意一个「。」改成「．」，再跑 → 退出码 **1**（规约偏离已登记版本）。
3. **改回**：把那个标点改回「。」，再跑 → 退出码 **0**。

再试两件更硬的：

4. **删一条锚**：删掉 `anchor/anchor_chain.jsonl` 任意一行 → 退出码 **2**（锚链断裂）。
5. **改自己**：在 `fireup.py` 里加一行注释，再跑 → 退出码 **3**（校验器本体被改动）。此时要 `python3 fireup.py init --rekey --reason "写明原因"` 才能重登记——**原因必填，且必须追加 `anchor/rekey_log.jsonl` 一条记录**；把那条记录删掉，闸1.5 会再拒你一次。这就是「改自己可以，抹掉痕迹不行」。
