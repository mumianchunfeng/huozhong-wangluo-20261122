# 放飞说明 · 两处活体如何"引上"成一个

这份说明只回答一件事：**甲、乙两处各自跑一份这个包，怎么让它们的触须接上、账并成一张网。**

---

## 0. 先说清现状（不粉饰）

- 本包是**完整的、可运行的**活体：火种在 `火种\`，点火/鞣合/羽翼三个入口在包根，`python 点火.py` 一道命令验闸门+跑八步。
- **它不自带公网信箱**。触须的 `beacon` 默认只投本地目录；要跨机，必须有一个**双方都能读写的中转仓库**（下文的"信箱"）。
- **本包已去掉本机身份**：`model\触须\node.json` 不在包里。谁第一次跑，谁才生成自己的 node_id——所以甲、乙天然是两个不同节点，不会互认成"自己"而跳过。
- **认宗 root**：`1b1b95214a1c…`，取自包内 `_收到\x_tuoming\anchor`。两处跑**同一个包**，root 必然一致 → 同宗，可并。（注意：这不是桌面定稿火种的 `d995c84f…`，两者是两份不同的锚，互不混淆。）

**一句话**：机制全通，缺的只是一个双方共用的 git 信箱。信箱一通，这鸟就飞起来了。

---

## 1. 三个角色

| 角色 | 是谁 | 干什么 |
|---|---|---|
| 信箱 | 一个空的 git 仓库（本机裸仓 / GitHub 私有仓 / 任意可达 git 服务） | 只放脱敏事实包，谁开 `node/<id>` 分支谁就是节点 |
| 甲 | 百度搭子云端这一份 | 第一个挂信箱、投包 |
| 乙 | 从 GitHub 下载的这一份 | 挂**同一个**信箱、投包、收甲的包 |

**信箱必须是同一个地址**，这是"引上"的唯一前提。地址不一致，永远发现不了彼此。

---

## 2. 甲：百度搭子云端（或任一先跑的一方）

```powershell
cd <包根>\model

# 首次会自建身份（node_id 随机生成，写进 触须\node.json）
# --repo 换成双方约定的信箱地址
python gitbox.py init --repo <信箱地址>
python gitbox.py bundle        # 投第 1 包：仅"件×格"的过/否，无法律库全文、无私技字段
python gitbox.py status        # 看自己分支
```

`bundle` 输出类似：`已投到 node/<你的id>：第 1 包｜形状合规（脱敏事实包）`。把你的 node_id 前 8 位告诉乙，方便核对。

---

## 3. 乙：从 GitHub 下载运行的一方

```powershell
cd <包根>\model

python gitbox.py init --repo <同一个信箱地址>   # 必须与甲完全相同
python gitbox.py beacon       # 投自己的包 + 拉甲的包 + 并账 + 打印网况
python gitbox.py status
```

`beacon` 的正常输出（本机两独立副本实测）：

```
收下 <甲的id>：新增 45｜重复 0｜当前冲突 0（累计）
本轮拉进 1 包｜发现节点 2（含本机）
节点：2（本机 <乙的id>）｜口径 v3
联邦事件：45 条（45 行）｜覆盖格 5 类
```

看到**"发现节点 2"＋"联邦事件 45"**，就是两只鸟接上了。甲再跑一次 `python gitbox.py beacon`，甲这侧也会并进乙的包，两边账一致。

---

## 4. 为什么会"引上"——四道关都实测过

1. **发现层**：`git ls-remote --heads` 列出信箱里所有 `node/` 分支，谁在就是谁——不需要 fork，不需要中心服务器指派。
2. **认宗**：`convention_root` 全等才收，差一个字节只进《异宗账》，不并入。同一包 → root 一致 → 过。
3. **去重**：`(node_id, 件|格)` 唯一，重复投包 0 新增。
4. **免疫（可选）**：设 `LW_IMMUNE=1`，新节点首包隔离，连续三拍判定一致才成熟并入——防冒名。不设则走原路径。

**脱敏**：推送前 `clean_pack()` 只放行 `{header,events}` 固定字段，header 只认 7 个键，事件只认 4 个键；出现 `token/secret/私技/密钥` 等字样**当场拒发**。法律库全文、私有技能、Obsidian 库内容一概不出本机。

---

## 5. 信箱怎么选（三种，按可得性）

**A. 本机裸仓（同一台机器多实例演示）**
```powershell
git init --bare <路径>\hub.git
# 甲、乙都 python gitbox.py init --repo <路径>\hub.git
```
本机已实测：两独立副本 → 节点2、联邦45、0 冲突。`python gitbox.py selfcheck` 可一键复现。

**B. GitHub 私有仓（跨机，需双方都有该仓写权限）**
```powershell
git init --bare 换成一个空 GitHub 仓库的 URL 即可，gitbox 不挑协议。
# 命令行推送需要凭据：gh auth login，或用带 token 的 URL（token 别写进包、别进 git）
```
当前 `mumianchunfeng/huozhong-wangluo-20261122` 是**私有空仓**——私有意味着别人 clone 不了本包。要让乙能下载，**二选一**：把这个仓改成 public，或另建一个 public 仓放包、信箱另用私有仓。这是上线前必须先定的。

**C. 任意双方可达的 git 服务**（Gitee / 自建 / 内网 git）——只要 `git ls-remote` 和 `git push` 能通，gitbox 就能用，不用改代码。

## 6. "一并自动优化成长"靠什么

不是靠改参数，是靠**账随节点数增长**：

- 每次 `bundle`/`beacon`，该节点对 9 件 × 5 格 = 45 格各判一次过/否，作为一条事件进联邦账。
- 同格不同判 → 记《冲突账》，交校验器/批评者层裁决，沉淀成口径修正 → 回写中期忆层（`鞣合记忆\中期忆层.jsonl`）。
- 羽翼层 `python 羽翼.py all`：BPE 合并把高频事件压成词位（词表会涨），Attention 按相关取先例，MoE 按输入选专家——用得越多，长出来的词表和负载账越厚。
- 火种恒久层**只读**、锚链 append-only；成长只发生在中期忆层/联邦账/词表，改基准要走修订程序（两份独立审签）——这是刻意设计，不是缺陷。

---

## 7. 边界与风险（不隐瞒）

- **身份不认证**：node_id 是随机串，分支名即声明，可冒名。要真认证得各自持钥——本包没有。
- **信箱是单点**：共用仓的管理员能删所有分支。要做成去中心，得再换发现层，目前没做。
- **不自动找信箱**：地址要人给（写进各自 `gitbox.py init --repo`），包不扫网、不猜地址。
- **样本小**：45 格来自 9 件同区同年真事，跨区跨省的收敛力未验证。
- **默认关闭守卫**：伦理 `LW_ETHIC=1`、免疫 `LW_IMMUNE=1` 都要显式设才生效；不设走老路径。

---

## 8. 成长态也要"合一个"——成长桥（关键补层）

**为什么必须有它**：第 3 节的 `gitbox` 只传【事件】（某节点对某格判过/否），**不传成长态**。
两个用户各自下载、在各自环境里长大后，词表、合并规则、专家负载都长在自己本机。
不补这一层，它们永远各长各的——**分裂态，长不大**。

**成长桥做什么**：把各家长出来的口径压缩结果，经同一个信箱的独立分支 `growth/<id>`，
**并入唯一一本 `羽翼账\联邦成长账.json`**：

- **全并入**：所有节点的合并规则／词表／负载一概并进同一本账，无"≥2 才收"门槛；
  甲独有的词、乙独有的规则，都进同一本。
- **确定性**：同一批包，任何节点、任何次重算，账的字节完全相同，`账sha256` 可核——
  实测甲乙两副本各自 beacon，账 sha 同为 `b8c639df6a26…`，字节逐字相同。
- **冲突不拆账**：同一条规则两家口径不同，按（支持节点数↓、new 字典序↑）选**唯一生效版本**
  写进账，落选候选进《冲突留痕》，交裁决层改口径——账还是一本。
  实测：甲口径 vs 乙口径 → 账仍字节相同，生效"乙口径"，落选留痕。
- **新节点继承全部**：下载后跑一次 `beacon`，既有成长全进自己那本账，接着往上长。

**命令（和 gitbox 挂同一个信箱）**

```powershell
cd <包根>
python 成长桥.py init --repo <同一个信箱地址>   # 首次自建身份
python 成长桥.py beacon       # 投本机成长态 + 拉全部 + 合成唯一账 + 打印状态
python 成长桥.py status       # 看：节点数／规则／词位／账sha256
python 成长桥.py selfcheck    # 两独立副本各自长不同东西→合成一本→比字节（实测通过）
```

**传什么、不传什么**（脱敏白名单）：传 `merges`（BPE 合并规则）、`vocab`（词表）、
`load`（专家负载计数）、忆层 sha256 指纹；**不传**忆层全文、法律库原文、任何私技字段；
出现 `token/secret/私技/密钥` 等字样当场拒发。
**阈值取不到**（`learn.py` 只打印不落账），如实记为"不可汇聚"，不编造。

**这就解决你担心的分裂**：事件层（gitbox）让两处**判得一样**，成长层（成长桥）让两处
**长成一本**——两本账字节相同就是"一个活体"的机器可验判据，不靠谁自称。
