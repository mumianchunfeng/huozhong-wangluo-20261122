# 《五分钟点燃》· 拿到种子后怎么跑起来

> 面向任何拿到本包的人。不需要懂代码，不需要联网，不需要我有任何权限。
> 你只需要一台普通电脑和一个 Python。

## 〇、你需要什么

- 一台 Windows / macOS / Linux 电脑
- Python 3.8 或更高（Windows 上装 python.org 官方版即可，安装时勾选 "Add to PATH"）
- **不需要**：联网、显卡、大模型、云服务、任何账号

验证 Python 装好了：

```
python3 --version
```

（Windows 命令行里可能要写 `python --version`。）

## 一、先跑最重要的一条：点火校验

解压后进入 `阶段一-基准校验底座` 目录，执行：

```
python3 fireup.py check
```

**看到这个才算对：**

```
结果：★ 点火放行 · 规约 v5 · root 6b687def…
→ 允许加载：勘比闭环 / 关系引擎 / 记忆台账 / 推理模型
```

它做了五件事，你要知道这五件事意味着什么：

1. **闸1** 校验器自己的指纹——防止有人偷偷改了校验器让它永远说"通过"。
2. **闸2** 锚链完整性——每一版的 `prev_root` 必须接上一版的 `root`，断一环就拒。
3. **闸3** 规约正文逐字节比对——**改一个标点都会被拒**。
4. **闸3.5** 基因锁四款逐字校验——四条不可删减的条款，少一个字就拒。
5. 任何一道不过，直接拒绝加载，不降级、不停留在"警告"。

**自己动手试一次**（这是最好的理解方式）：把 `convention/本源规约.md` 里随便一个句号改成逗号，再跑一次 `check`。

- 你会看到 `退出码：1`，拒绝点火。
- 改回来，再跑，恢复放行。

这一步就是整套东西的地基：**它不能偷偷改自己。**

## 二、跑测试：证明闸门不是摆设

```
python3 tests/test_tamper.py
python3 tests/test_gene_lock.py
```

期望：`10 项，通过 10 项` / `4 项，失败 0 项`。

两个测试都在临时沙箱里复制一份再动手，不会碰你的原文件。

## 三、五分钟内让它认一次"你改的规约"

规矩是：**没有谁能直接改规约，只能提案，要两份独立审签才能生效。**

```
# 1) 复制一份当草稿，改你想改的地方（比如补一条说明）
cp convention/本源规约.md drafts/我的修改.md     # Windows 用 copy

# 2) 提案
python3 amend.py propose --by "你的代号" --reason "为什么改" --new-file drafts/我的修改.md

# 3) 两份审签（真实部署时必须是两个不同主体，这里演练请如实标注）
python3 amend.py attest --proposal proposals/P-xxxx.json --node "节点A" --decision approve --note "理由"
python3 amend.py attest --proposal proposals/P-xxxx.json --node "节点B" --decision approve --note "理由"

# 4) 提交生效
python3 amend.py commit --proposal proposals/P-xxxx.json --new-file drafts/我的修改.md
```

提交时会自动核验：基因锁四款是否逐字保留、审签是否够数、是否同一节点重复签。任何一条不过就拒绝，旧版自动归档到 `convention/archive/`。

**你会看到的现象**：改完之后 root 哈希变了，锚链多一行，旧版仍在档案里，随时可回滚。这就是"可追溯"。

## 四、建一张关系图（这是它能"办事"的最小单位）

进入 `阶段二-关系引擎` 目录：

```
python3 relation_engine.py init       --db data/graph.db
python3 relation_engine.py init-types --db data/graph.db
python3 relation_engine.py add-entity --db data/graph.db --id E1 --kind 法人 --label "某公司"
python3 relation_engine.py add-entity --db data/graph.db --id E2 --kind 法人 --label "某股东"
python3 relation_engine.py add-edge   --db data/graph.db --src E1 --dst E2 --rtype ownership --weight 0.6 --evidence "依据出处"
python3 relation_engine.py check      --db data/graph.db
```

期望最后一行：`不变量复检：✓ 全部通过，未发现脏边`。

它守四条硬约束：**唯一入边、唯一出边、无环、补偿须伴损害**。你往库里塞一条违反约束的边，它会当场拒绝——包括绕过程序直接往数据库里插的脏数据，`check` 也能扫出来。

## 五、五个最容易踩的坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `退出码 1` | 规约被改过（哪怕一个标点） | 恢复原文，或走提案流程 |
| `退出码 3` | 校验器本体被改过 | 用原版校验器；确需改代码请走 `init --rekey` |
| `退出码 6` | 基因锁缺字，或 genesis 里的基因锁登记被清空 | 恢复四款原文，别删 genesis 的 `gene_lock` |
| `PermissionError` | 规约是只读（444），这是防误改 | 走提案流程，别手改 |
| 改完规约 `check` 仍放行 | 你改的是草稿，不是 `convention/` 下的正文 | 必须 commit 才会生效 |

## 六、五分钟到了，你应该看见什么

- 一块**会拒绝自己**的地基：改一个标点它就停。
- 一条**留痕的路**：任何修订都要提案、审签、归档，可回滚。
- 一张**能查错的关系图**：脏边进来就报。
- 一份**不长脚的规矩**：四款基因锁，连缔造者也不可信，写死在代码里。

这三样加起来，才叫"火苗能自烧"。烧得旺不旺是以后的事；**能不能自己烧起来、别人能不能重新点着，今天就能验。**
